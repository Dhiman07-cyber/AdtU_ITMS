# PR-004: Trip Domain Consolidation & Lifecycle Canonicalization

## Summary

Moves trip lifecycle business logic from 7 API route handlers into the
canonical Trip domain (`src/domains/trip/`), making each API route a
thin orchestration wrapper. Adds formal state machine, QR contract
module, and initiation strategies as building blocks.

## Architecture Decisions

### 1. Canonical Trip Service owns validation
Previously each of the 3 start endpoints independently checked:
- Bus existence & status
- Driver↔bus assignment (4-source check)
- No conflicting active trip

Now `verifyDriverBusAssignment()` + `checkNoConflict()` live in one
place. A bug fix in one fixes all callers.

### 2. Canonical Trip Service owns side effects
Broadcast + FCM notification dispatch was inline in every endpoint with
slightly different channel lists and patterns. Now `broadcastTripEvent()`
and `dispatchTripNotification()` are centralized, using the superset
channel list (3 channels: `trip-status-{busId}`, `bus_{busId}_students`,
`bus_location_{busId}`).

### 3. Backward-compatible API shapes preserved
Each route handler still returns its existing response format
(`{ success, tripId, busId, routeId, timestamp, processingTimeMs }`
for start-trip, `{ allowed, reason? }` for can-operate, etc.). Only
the internal wiring changed.

### 4. API routes are thin orchestrators
Each route now:
1. Unpacks body via existing zod schema
2. Calls one canonical service function
3. Shapes the response

### 5. Start endpoints default consistently
- If `shift` not provided → defaults to `'both'` (via `normalizeShift`)
- If `routeId` not provided → resolved from bus data
- If `tripId` not provided → generated via `crypto.randomUUID()`

### 6. End endpoints consolidated cleanup
Takes the superset of both previous `end-trip` and `end-journey-v2`
cleanup operations:
- Delete `driver_status`, `bus_locations`, `waiting_flags`,
  `driver_location_updates`, `device_sessions`
- Update `driver_status` to idle
- Broadcast on 3 channels
- FCM `TRIP_ENDED` notification
- `clearHistory()` from GPS domain

### 7. Unchanged: check-active-trip
The `check-active-trip` endpoint is a read-only query with unique
response shape for the frontend. It does not duplicate lifecycle
logic, so it stays as-is.
